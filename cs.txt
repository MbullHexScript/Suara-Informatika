SUARA INFORMATIKA — PowerShell Windows / CMD
Domain: https://suarainformatika.vercel.app

Jalankan dari folder project. Semua perintah di bawah SATU BARIS.
Tidak ada token di file ini. Isi konfigurasi melalui .env lokal, jangan kirim ke chat.

1. Rapikan env lama dan buat file import Vercel (tidak mencetak nilai rahasia):
node scripts/ops.mjs prepare

2. Isi .env dengan URL/key Supabase yang AKTIF dan token bot BARU.
   SUPABASE_SERVICE_ROLE_KEY dan TELEGRAM_BOT_TOKEN tidak boleh berawalan VITE_.
   TELEGRAM_OWNER_ID = Telegram User ID pemilik, bukan ID grup.
   TELEGRAM_ADMIN_CHAT_ID = chat admin lama, boleh beberapa ID dipisah koma.
   WEB_ADMIN_EMAIL = email akun Supabase Auth milik pengelola dashboard.
   SUPABASE_ACCESS_TOKEN = personal access token untuk menjalankan migrasi.
   Jalankan prepare lagi setelah mengganti kredensial.

3. Diagnosis koneksi (read-only, tidak membuat laporan atau pesan):
node scripts/ops.mjs diagnose

4. Jalankan migrasi 002 + 003 pada project lama dan daftarkan pemilik/admin:
node scripts/ops.mjs migrate
node scripts/ops.mjs bootstrap

5. Import .env.vercel melalui Vercel Settings > Environment Variables > Import.
   Hapus VITE_SUPABASE_SERVICE_ROLE_KEY dan VITE_TELEGRAM_BOT_TOKEN yang lama.
   Hapus/benahi SUPABASE_URL atau key lama yang konflik. Pilih Production.
   Deploy kode terbaru (bukan redeploy commit lama).
   Jika memakai CLI yang sudah login dan terhubung:
npx vercel --prod

6. Pasang webhook setelah deployment terbaru aktif:
node scripts/ops.mjs webhook

7. Cek status webhook:
node scripts/ops.mjs diagnose

8. Buka Telegram dengan akun pemilik, kirim /start, kemudian /undang.
   Anggota membuka chat pribadi bot, /start, lalu menempelkan token SI-….
   /anggota untuk daftar anggota; /cabut USER_ID untuk mencabut akses.

9. Tes unit/backend dan build (tidak menyentuh data production):
npm test
npm run build

10. Tes production secara sengaja: membuat 3 laporan bertanda [UJI SISTEM]
    dan mengirim notifikasi ke seluruh anggota aktif. Nomor WA uji harus
    disediakan melalui TEST_WHATSAPP di .env (nomor milik penguji).
node scripts/ops.mjs smoke --send

11. Proses ulang antrean yang jatuh tempo:
node scripts/ops.mjs retry

12. Untuk retry otomatis, panggil endpoint ini dari scheduler setiap menit
    dengan header Authorization: Bearer <CRON_SECRET>. Scheduler Vercel
    bawaan disetel harian agar kompatibel dengan Hobby; gunakan scheduler
    eksternal/Pro bila memerlukan retry dalam hitungan menit.
    POST https://suarainformatika.vercel.app/api/telegram/retry

Contoh curl yang aman untuk ditempel (tidak ada JSON multiline):
curl.exe -sS https://suarainformatika.vercel.app/api/health

DI BROWSER:
https://suarainformatika.vercel.app/api/health
https://suarainformatika.vercel.app/laporan

Jangan menempelkan URL yang berisi token bot ke browser atau screenshot.
Gunakan scripts/ops.mjs webhook agar token tidak masuk history browser.
Forbidden saat memanggil webhook tanpa secret header adalah normal.
Health OK hanya membuktikan endpoint hidup, bukan database/bot sehat.
